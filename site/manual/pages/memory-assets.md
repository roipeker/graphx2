# Memory assets

Not every asset starts in a Flutter bundle or at a URL.

Sometimes you already have the bytes: a file picker returned them, a database stored them, another package decoded a container, or your app generated them at runtime.

GraphX can use those bytes directly.

## Bytes can stay as bytes

If the data is not an image, the asset store can simply hold the memory block:

```dart
final bytes = await stage.assets.bytesMemory(
  sourceBytes,
);
```

With the default `cache: false`, GraphX just gives the same bytes back through the async API. No cache entry is created.

That keeps the memory helper consistent with the rest of `GAssets` without pretending every byte buffer needs ownership or decoding.

## Decode an image from memory

For a static texture:

```dart
final texture = await stage.assets.textureBytes(bytes);
```

For a source that may contain multiple animation frames:

```dart
final imageData = await stage.assets.imageBytes(bytes);
```

And when the call site explicitly wants all timed frames:

```dart
final sequence = await stage.assets.textureSequenceBytes(bytes);
```

The decode path is the same Flutter image codec used by bundle and URL assets. The difference is only where the source bytes came from.

## Memory caching is opt-in

Memory methods default to `cache: false` because a raw `Uint8List` has no stable identity beyond the object you happen to hold.

If you want the runtime store to cache a memory asset, give it a key:

```dart
final texture = await stage.assets.textureBytes(
  bytes,
  key: 'avatar:$userId',
  cache: true,
);
```

When `cache: true`, the key becomes the identity of that decoded resource and the runtime store owns the cached GraphX texture/sequence lifetime.

With the default `cache: false`, a decoded owned texture/sequence is not retained by `GAssets`; the caller is responsible for disposing that uncached resource when it is no longer needed.

That means the key must represent the content/version correctly. Reusing the same key for different bytes tells GraphX they are the same cached asset.

A versioned key is often clearer when data can change:

```dart
final key = 'avatar:$userId:v$revision';
```

## Decode toward the size you need

Memory decoders accept the same target dimensions as bundle/network decoders:

```dart
final thumbnail = await stage.assets.textureBytes(
  bytes,
  targetWidth: 128,
);
```

The resize request goes into Flutter's codec, so this can avoid decoding a much larger backing image than the scene needs.

## The scene does not care where the texture came from

Once decoding finishes, a memory texture is an ordinary `GTexture`:

```dart
final image = addChild(GImage(texture));
image.setPosition(80, 60);
```

The node/rendering side is intentionally source-agnostic. Bundle file, network response, generated bytes, database blob—the result enters the same retained texture/image model.
